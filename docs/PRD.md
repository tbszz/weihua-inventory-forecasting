# 安全库存动态预测与缺货预警系统 PRD

**版本**：V0.1（黑客松 MVP）  
**日期**：2026-11-09  
**产品类型**：供应链数据分析 / 算法辅助决策系统  
**项目判断**：这是一个以统计预测、库存控制和风险预警为核心的算法产品，前端负责解释和执行结果。

## 1. 文档边界

本 PRD 根据用户提出的“现在要做这个项目，出一个 PRD”以及引用的历史沟通内容编写。两份 XLSX 仅作为业务数据样例读取；表格中的字段、公式和历史数据被视为数据来源，不视为对本 PRD 的指令。

## 2. 一句话定义

系统每天读取历史出库、入库、当前库存、采购周期、实际交货天数和未来需求，计算每种物料的动态安全库存、再订货点、预计缺货日期和建议采购量，并给出可追溯的算法依据。

## 3. 背景与问题

当前库存管理主要依赖历史平均用量和固定阈值。需求会集中发生，供应商交期会波动，安全库存又通常按月或双月人工调整，因此会出现以下问题：

- 物料未跌破固定阈值前，系统无法识别未来采购周期内的缺货风险。
- “日均用量 × 采购周期”只覆盖平均需求，无法覆盖集中领用和交期延迟。
- 安全库存、采购提前期需求和在途库存没有被统一计算，采购申报缺少量化依据。
- 不同物料、不同单位和不同供应商的风险差异没有被体现。

历史沟通中的典型例子是：日均消耗 3 件、采购周期 5 天、库存基准 15 件时，若某日集中领用 15 件，库存可能在下一批到货前耗尽。产品要解决的是“提前判断何时会缺货、需要补多少”，而不是简单显示当前库存。

## 4. 产品目标与非目标

### 4.1 目标

1. 将固定阈值升级为按物料、需求波动和交期波动动态计算的安全库存。
2. 在物料真正缺货前给出风险日期、风险等级和建议动作。
3. 让采购员能看到推荐值的组成：历史需求、未来已知需求、交期、服务水平和库存位置。
4. 以可解释、可回放的算法作为 MVP，后续再引入机器学习。
5. 用真实业务数据验证预测准确性和库存收益。

### 4.2 非目标（MVP 不做）

- 不替代 ERP/WMS 的入库、出库、采购审批和主数据维护。
- 不在第一版承诺使用深度学习或大模型直接生成采购决策。
- 不自动下采购订单；系统只生成建议，保留人工审核和审批。
- 不把不同计量单位直接相加；KG、M、PC 等单位必须先完成物料级换算或分开建模。

| 用户 | 主要任务 | 需要的结果 |
|---|---|---|
| 仓库管理员 | 查看库存状态、确认出入库数据 | 今日库存、在途、风险物料清单 |
| 采购员 | 决定何时采购、采购多少 | 建议采购量、建议下单日、交期依据 |
| 计划员/生产管理 | 评估未来项目需求对库存的影响 | 需求预测、BOM/订单需求叠加后的缺口 |
| 供应链主管 | 衡量缺货与库存占用的平衡 | 服务水平、库存金额、缺货风险趋势 |
| 算法/数据人员 | 校验模型效果、调整参数 | 数据质量、预测误差、回测结果、版本记录 |

## 6. 典型用户故事

1. 作为采购员，我希望按“高风险、预计缺货日期、建议采购量”排序物料，以便先处理最紧急的申报。
2. 作为仓库管理员，我希望看到某个物料未来 7/14/30 天的库存曲线，以便核对系统预警是否合理。
3. 作为计划员，我希望导入未来 BOM 需求后，系统重新计算库存缺口，而不必手工修改安全库存。
4. 作为主管，我希望知道推荐安全库存比现行阈值多/少多少，以及减少了多少缺货风险。
5. 作为算法人员，我希望查看每次计算使用的数据时间范围、参数和模型版本，以便复盘。

### 7.3 数据质量规则

- 物料编码、日期、数量为必填；数量必须带单位。
- 出库数量统一转为正的需求量，入库数量统一转为正的供应量，保留原始正负号供追溯。
- 去重键优先采用物料凭证 + 物料凭证项目；采购入库采用采购订单 + 行号。
- 过滤或单独标记盘点、初始余额、移库、冲销等非真实需求移动类型。
- 若物料同时有 KG 和 M，必须配置换算关系或分别计算，不允许隐式相加。
- 实际交货天数小于 0、缺少实际到货日、数量异常等记录进入数据质量清单，不直接参与交期模型。

## 8. 产品范围与功能需求

### 8.1 数据接入与数据质量

**功能**：支持 XLSX/CSV 导入，按模板映射字段；保留原始文件、导入批次和校验结果。

**验收**：导入后显示成功行数、失败行数、重复行数、单位异常和日期异常；失败记录可下载。

### 8.2 物料库存总览

展示物料编码、描述、单位、当前可用库存、在途库存、已分配库存、动态安全库存、再订货点、库存可支撑天数、风险等级、预计缺货日期。

支持筛选：物料、物料类别、供应商、风险等级、仓库、单位；支持按预计缺货日期和缺口数量排序。

### 8.3 物料详情与库存曲线

展示过去 30/90/180 天出库趋势、入库趋势、库存曲线、未来需求、预计到货和预测库存曲线。鼠标悬停时显示日期、预测/实际标识、数量和数据来源。

### 8.4 动态安全库存计算

系统按物料和单位计算：

- 历史需求均值、标准差、变异系数、需求间隔。
- 预计采购提前期、交期中位数、P90 交期、交期标准差。
- 未来已知需求、当前可用库存、在途库存和已分配库存。
- 目标服务水平对应的 Z 值和动态安全库存。

支持参数覆盖：服务水平、预测窗口、最小安全库存、最大库存上限、是否纳入未来订单、是否采用供应商级交期。

### 8.5 缺货风险预测与预警

系统预测未来 7/14/30 天或一个采购周期内的库存变化，输出：

- 预计首次库存小于 0 的日期。
- 预计首次库存低于再订货点的日期。
- 预测缺口数量和缺口持续天数。
- 风险等级：红色（预计缺货/已缺货）、橙色（采购周期内跌破再订货点）、黄色（安全边际不足）、绿色（可保障）。

预警支持站内消息和导出；短信、企业微信等通知作为后续扩展。

### 8.6 采购建议

对于红色或橙色物料，生成建议下单日、建议采购量、预计覆盖日期和建议供应商。建议量默认采用：

`建议采购量 = 目标库存位置 - 当前库存位置`

其中目标库存位置由未来覆盖窗口需求 + 安全库存 + 已知需求构成，并按最小采购量、包装量和单位精度向上取整。

采购员可以调整建议量、填写原因并标记“已申报/暂缓/忽略”；系统记录人工覆盖值，不覆盖算法原始结果。

### 8.7 算法解释与回测

每条建议必须能展开查看：数据时间范围、需求均值/波动、交期统计、服务水平、公式版本、输入快照和计算时间。

支持选择历史日期进行回测，比较“现行固定阈值”和“动态模型”的缺货次数、平均库存、服务水平和预警提前量。

## 9. 算法方案

### 9.1 MVP 采用“统计预测 + 库存控制”

MVP 不直接上复杂机器学习，先保证数据可解释和结果可验证：

1. 将出库流水按物料、单位、日期聚合，补齐无出库日期为 0。
2. 需求基线采用最近 N 天加权移动平均；对集中领用使用 P50/P75/P90 分位数和异常值截尾。
3. 交期基线采用实际交货天数的中位数，风险交期采用 P90；样本不足时回退到物料配置的采购周期。
4. 将未来已知 BOM/订单需求作为确定性需求单独叠加，不用历史模型重复预测。
5. 使用需求和交期波动计算安全库存，使用日级库存滚动模拟识别缺货日期。

### 9.2 核心公式

符号定义：

- `μd`：日需求均值；`σd`：日需求标准差。
- `μL`：平均交期；`σL`：交期标准差；`L90`：P90 交期。
- `z`：目标服务水平对应的标准正态分位数。
- `Dknown(L)`：采购提前期内已知未来需求。

建议安全库存：

`SS = z × sqrt( μL × σd² + μd² × σL² )`

建议再订货点：

`ROP = Dknown(L) + μd × μL + SS`

保守模式可将 `μL` 替换为 `L90`；对于集中领用明显的物料，需求项使用 P75/P90 场景值。

库存位置：

`IP = 可用库存 + 合格在途库存 - 已分配库存`

风险预测：从当前日期起逐日扣减预测需求、叠加预计到货，计算 `IP(t)`；当 `IP(t) < 0` 时记录预计缺货，当 `IP(t) < ROP` 时记录补货风险。

### 9.3 预测模型升级路线

- V0.1：加权移动平均 + 分位数 + 交期统计 + 规则模拟。
- V0.2：按物料类别选择 Croston/ETS/Prophet 等适合间歇需求或季节性的模型，并以回测结果自动选优。
- V1.0：将项目计划、维修任务、供应商、价格和季节因素纳入特征，使用可解释的梯度提升模型预测需求和交期。

任何模型升级都必须通过离线回测和线上灰度，不能只凭单次预测误差上线。

### 10.4 数据质量页

显示导入批次、字段映射、异常类型、异常数量、可忽略/需修复状态和处理记录。

## 12. 指标与验收标准

### 12.1 算法指标

- 需求预测：MAE、MAPE（需求为 0 时改用 WAPE/MASE）。
- 交期预测：MAE、P90 覆盖率。
- 缺货风险：预计缺货日期提前量、缺货召回率、误报率。
- 库存效果：服务水平、平均库存、库存周转、库存占用金额。

### 12.2 MVP 验收

1. 能成功导入两份样例数据，正确识别普通件与 KG/M 双单位物料。
2. 对每个物料产出动态安全库存、再订货点、预计缺货日期、风险等级和建议采购量。
3. 任一建议均可展开查看输入数据、参数和公式，不出现不可解释的黑盒分数。
4. 将回测日期设为历史日期时，系统能复现当时可见数据，不使用未来数据泄漏。
5. 修改未来需求、库存或交期参数后，风险日期和采购建议会重新计算。
6. 采购员可以导出建议清单，并将每条建议标记为已申报、暂缓或忽略。
7. 数据质量异常不会静默进入模型，导入结果能定位到原始记录。

## 14. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 历史数据不足六个月 | 需求波动估计不稳 | 标记置信度，回退到采购周期和人工参数 |
| 未来需求缺少日期 | 无法精确模拟缺货日期 | 按需求窗口或最晚日期处理，并显示假设 |
| 入库明细含初始余额/移库 | 交期和需求被污染 | 通过移动类型白名单过滤并保留异常清单 |
| 单位混用 | 库存数量失真 | 物料级单位校验和换算配置，禁止自动猜测 |
| 供应商交期样本太少 | P90 不稳定 | 采用物料默认采购周期或供应商类别先验 |
| 只追求不缺货 | 库存过高 | 同时展示服务水平与库存占用，支持分级服务目标 |

## 15. 待确认事项

1. 目标预警窗口是未来 3、7、14、30 天，还是至少覆盖一个采购周期？
2. 当前库存是否已扣除冻结、已分配和不可用库存？
3. 未来需求是否可以取得明确需求日期和需求来源？
4. 供应商是否存在分批到货、部分收货和取消订单？
5. 物料是否需要按 A/B/C 或关键设备等级设置不同服务水平？
6. 建议采购量是否受最小采购量、包装量、供应商配额或预算约束？
7. 首个 MVP 是做离线 Excel/网页演示，还是直接对接 ERP/WMS 接口？

## 16. 推荐的黑客松演示闭环

选取三类样例：普通 PC 物料、需求波动明显的物料、KG/M 双单位工字钢。演示“导入数据 → 选择预测窗口 → 查看动态安全库存 → 修改一笔未来需求或交期 → 风险日期前移 → 导出采购建议”的完整流程，重点展示算法解释和回测对比，而不是只展示一个预测数字。
